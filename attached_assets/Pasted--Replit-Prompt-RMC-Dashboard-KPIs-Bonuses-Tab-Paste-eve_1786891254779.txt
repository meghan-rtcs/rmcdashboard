## 1. Core concept

Three departments: **Property Management**, **Maintenance**, **Bookkeeping**.

Each department has 3-4 KPIs. Each KPI has three achievement tiers (**Good / Better / Best**), and each tier pays a dollar amount. Department KPI dollars are earned by the department as a unit and split among its members. Some KPIs are individual instead of departmental.

Quarterly cycle. The tab shows the current quarter in progress plus locked historical quarters.

## 3. Configuration model (important)

All KPI definitions, thresholds, and dollar amounts must live in a single editable config (JSON file or a `kpi_config` DB table, your call - prefer DB with a simple admin edit screen if that isn't a large lift). Nothing about thresholds or payouts should be hardcoded in UI or calculation code.

Each KPI config record needs:

- `id`, `department`, `label`, `description`
- `scope`: `department` or `individual`
- `assigned_to`: null for department-scope, employee id for individual
- `data_source`: which AppFolio report or external source feeds it
- `direction`: `higher_is_better` or `lower_is_better`
- `unit`: `percent`, `days`, `count`, `currency`
- `tiers`: `{ good: {threshold, payout}, better: {threshold, payout}, best: {threshold, payout} }`
- `active`: boolean, and `effective_quarter` so changing thresholds mid-year doesn't retroactively rewrite closed quarters

Thresholds below are the client's first pass and **will change** before rollout. Build so they can be swapped without a redeploy.

## 5. Bonus calculation and display

For a given quarter and employee:

```
earned = sum over department KPIs (tier_payout x employee_share_in_that_department)
       + sum over individual KPIs assigned to that employee (tier_payout)
```

Rules:

- If a KPI result falls below the Good threshold, payout is $0 for that KPI.
- Tier is the highest tier whose threshold is met, respecting `direction`.
- Thresholds expressed as ranges (e.g. "70-80%") should be stored as the lower bound of the band; the band's upper bound is implied by the next tier.
- Show both the earned dollars and the maximum possible dollars for the quarter, per employee and per department.

Display requirements:

- **Quarter selector** at the top. Default to the current quarter. Historical quarters render read-only.
- **Department view**: each department as a card or section, with its KPIs listed showing current actual value, tier achieved (color-coded), tier thresholds visible inline, and dollars earned vs. available.
- **Employee view**: a row or card per employee showing quarter-to-date earned, maximum possible, and a breakdown of which KPIs contributed. Fabian's card must clearly show his two department contributions separately.
- Every KPI value should be **clickable to a drill-down** showing the underlying records that produced it (the same pattern used elsewhere in this dashboard). This is the primary way the team will find bad AppFolio data.
- Flag KPIs where the underlying data looks unreliable - for example, work order KPIs where a large share of work orders are sitting in "New" or "Assigned" status with no further status movement. A visible data-quality warning is more useful here than a silently wrong number.

## 6. Quarter locking / snapshots

At quarter close, snapshot the computed KPI values and bonus amounts to a `quarter_results` table. Historical quarters must read from the snapshot, not recompute live. AppFolio records get edited retroactively and a bonus that has already been paid and discussed with staff cannot change afterward.

Include an admin action to re-snapshot a specific quarter, in case a correction is needed before payout, with a timestamp of when the snapshot was taken shown on historical views.
