Match the existing dashboard’s card styling, font sizes, and color conventions. Use the same CSS variables and patterns already in the project.

-----

## Part 1: Summary Bar

A single horizontal row with 6 tiles (one per role), separated by 1px borders. Each tile shows:

- A small colored status dot (green/amber/red/gray)
- The role abbreviation in small uppercase gray text (e.g. “PM”, “APM”)
- The role short name in bold (e.g. “Portfolio Manager”, “Assistant PM”)
- A score like “4/5 on tgt” showing how many KPIs are meeting target out of total — or “—” if no KPIs

The 6 roles in order: **PM** (Portfolio Manager), **APM** (Assistant PM), **LS** (Leasing Spec.), **BC** (Bookkeeping Coord.), **AA** (Admin. Asst.), **MS** (Marketing Spec.)

-----

## Part 2: Role Cards (2-column grid)

Each card has:

### Card Header

- **Score ring** (circle with border color matching overall status): shows “X/Y” (on-target count / total KPIs)
- **Role name** in bold
- **Meta line**: “· 3 people” then small colored dots with counts like “● 4 on track ● 1 at risk”
- **Overall status badge** (top-right pill): “On track” (green), “At risk” (amber), or “Off track” (red)

### KPI Rows (one per KPI inside the card)

Each row has, left to right:

- **Status dot** (10px circle): green if meeting target, amber if within 10% of target, red if below 90% of target, gray if no data
- **KPI name** in medium-weight text
- **Source badge**: a small rounded pill saying “BD” (warm tan background `#e8e0d4`, dark text `#6b5b3e`) for Buildium, or “RE” (blue background `#dbeafe`, dark blue text `#1e40af`) for RentEngine
- **Target** label: small “TARGET” in uppercase above the target value (right-aligned)
- **Value**: large bold number colored to match the status dot. Percentage values show “%” as a smaller suffix. Day values show “d”. Hour values show “h”.

### RAG (Red/Amber/Green) Logic

- For KPIs where higher is better (`direction: gte`): green if `value >= target`, amber if `value >= target * 0.9`, red if below that
- For KPIs where lower is better (`direction: lte`): green if `value <= target`, amber if `value <= target * 1.1`, red if above that
- If value is `None` (no data available): show gray dot and “—” as the value

### Overall Role Status

- If any KPI is red → role is “Off track” (red badge)
- Else if any KPI is amber → role is “At risk” (amber badge)
- Else if all KPIs green → “On track” (green badge)
- If role has no KPIs (Marketing Specialist) → show “—” and gray styling, with a centered italic message “No Buildium / RentEngine KPIs for this role”

## The 7 API-Calculable KPIs (with formulas)

These are the KPIs that have real data from the Buildium and RentEngine APIs. Wire them up to the cached data that the dashboard already pulls.

### KPI 1: Portfolio Occupancy Rate

- **Role**: Portfolio Manager
- **Source**: BD (Buildium)
- **Target**: ≥95%
- **Format**: percentage
- **Formula**: `(count of units where IsUnitOccupied == true) / (total active units) × 100`
- **Data**: Already available from `GET /v1/rentals/units` (the units data you already cache). Filter to active properties only (same filter the Buildium tab already uses).

### KPI 2: Delinquency Rate

- **Role**: Portfolio Manager
- **Source**: BD (Buildium)
- **Target**: ≤3%
- **Format**: percentage
- **Direction**: lower is better
- **Formula**: `(sum of TotalBalance where TotalBalance > 0 across active leases) / (rent roll total) × 100`
- **Data**: Already available from `GET /v1/leases/outstandingbalances` (your existing delinquency data) and `GET /v1/leases/rent` (rent schedules). Use the same outstanding balances and rent roll values the Buildium tab already computes.

### KPI 3: Showing Completion Rate

- **Role**: Assistant Property Manager
- **Source**: RE (RentEngine)
- **Target**: ≥95%
- **Format**: percentage
- **Formula**: `sum(showings_completed across all units) / sum(showings_scheduled across all units) × 100`
- **Data**: From `GET /reporting/leasing-performance/units/{unitId}` (RentEngine). This is a per-unit endpoint — iterate across all active RentEngine units and aggregate `showings_scheduled` and `showings_completed` fields from the `UnitLeasingPerformance` response. Use the current reporting period (e.g. last 30 days or current month). If this data isn’t already cached, add it to the RentEngine sync.

### KPI 4: Reconciliation Accuracy

- **Role**: Bookkeeping Coordinator
- **Source**: BD (Buildium)
- **Target**: 100%
- **Format**: percentage
- **Formula**: `(reconciliations without discrepancies) / (total reconciliations in period) × 100`
- **Data**: From `GET /v1/bankaccounts/{bankAccountId}/reconciliations` (Buildium). Pull reconciliation records for each bank account. If this data isn’t already cached, add it to the Buildium sync. **If not yet available, set to None (will show gray dash).**

### KPI 5: Rent Processing Accuracy

- **Role**: Bookkeeping Coordinator
- **Source**: BD (Buildium)
- **Target**: 100%
- **Format**: percentage
- **Formula**: `(rent/deposit transactions without reversals) / (total rent/deposit transactions) × 100`
- **Data**: From `GET /v1/leases/{leaseId}/transactions` and reversed payments. Look for reversed payment transactions as the error signal. **If not yet available, set to None (will show gray dash).**

### KPI 6: Vendor Compliance

- **Role**: Bookkeeping Coordinator
- **Source**: BD (Buildium)
- **Target**: 100%
- **Format**: percentage
- **Formula**: `(active vendors where TaxPayerId is not empty AND VendorInsurance.ExpirationDate > today) / (total active vendors) × 100`
- **Data**: From `GET /v1/vendors` with `status=Active` (Buildium). Check `VendorMessage.TaxInformation.TaxPayerId` for W-9 status, and `VendorMessage.VendorInsurance.ExpirationDate` for COI status. If this data isn’t already cached, add it to the Buildium sync.

### KPI 7: 1099 Compliance

- **Role**: Bookkeeping Coordinator
- **Source**: BD (Buildium)
- **Target**: 100% by Jan
- **Format**: percentage
- **Formula**: `(vendors where IncludeIn1099=true AND TaxPayerId is not empty) / (total vendors where IncludeIn1099=true) × 100`
- **Data**: Same vendors endpoint as Vendor Compliance. Filter to vendors where `TaxInformation.IncludeIn1099 == true`, then check if `TaxPayerId` is populated.
